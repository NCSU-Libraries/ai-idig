# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Materials for a 60-minute Zoom session from NC State University Libraries' Data Science Services, taught by Alp
Tezbasaran for NC State's **Instructional Design Interest Group (IDIG)** on Tuesday, November 24, 2026, 12:00 to
1:00 pm. Organizers: Jai Jackson and Daniel Davis. The repo and site are `ai-idig`
(<https://github.com/NCSU-Libraries/ai-idig>, published at <https://ncsu-libraries.github.io/ai-idig/>, short link
go.ncsu.edu/ai-idig); the local folder is `instruction/fall26/idig`. The format copies
`~/projects/dss/workshops/textiles-seminar`.

- **The title** is the wording of IDIG's announcement, which describes the session rather than naming it. It appears
  in `site/_quarto.yml`, `site/_variables.yml`, `site/index.qmd` and `site/slides/index.qmd`: change all four
  together.
- **What IDIG asked for,** in order: a brief introduction to vibe coding and where it's useful, how to get started and
  set up the tools, and a hands-on part where participants try it. A pre-session survey (16 responses) shaped the rest:
  almost everyone uses AI chat, 3 use coding assistants, and everyone who named a concern named accuracy.
- **Tools are limited by NC State's approved AI list.** Participants use Gemini with their NC State account. NC
  State's Gemini has no agentic coding tool, and the approved agentic options (Claude Team or Enterprise, ChatGPT
  Business or Enterprise) are paid plans, so Tier 2 is a demo that people with access can follow.
- **Private plan:** `instructor/` holds the plan, run sheet, talking points, chat snippets, the note for Jai to
  forward, the dry-run log, the demo runbook and `prompts.txt`. It's gitignored and is its own local git repo: commit
  there with `git -C instructor`.
- **The demo** is `demo/measurable-or-not/`, its own local git repo with no remote (tags `start` and `demo-ready`,
  fallback branches `live/*`). It's gitignored here. Run it from `instructor/runbook.md`.

**Design:**
- **One scrolling page** (`site/index.qmd`) in the shape of the Libraries' one-page guides: How to use this guide;
  Welcome (objectives, what you told us, about the activity); numbered sections; Wrapping up; Extra activities;
  Reference. Alp chose it for this session on 2026-11-23.
- **Three tiers, one activity.** Everyone builds "Measurable or Not?" in Gemini Canvas (section 3), takes it out as a
  file (section 4, "the wall"), then sees an agent upgrade it (section 5). Tier 0 (section 2) is a warm-up for
  newcomers during setup. Sections are named for the task, not the tool.
- **The deck is bookends only:** title, go link and QR code, the three DSS slides, a welcome slide with the presenter
  and a quick poll, the evaluation. Everything in between is taught from the guide. The title and welcome slides copy
  the DSS Google Slides template, as in the Data Wrangling with SAS deck; `theme/idig-slides.scss` styles both.
- **Boxes:** a prompt box (`.prompt`, labeled "Prompt for Gemini"), an agent prompt (`.prompt .agent`), the project
  instructions file (`.prompt .file`), the Answer key (a closed `callout-note`), and one Gotcha (`callout-warning`).
  A "**Check:**" line states something the participant can verify on screen.
- **Plain voice:** short sentences, no colon-led lists, no slogans, no dashes. Label and description pairs go in a
  small table.

The order, framing and timing were still open on 2026-11-23: `instructor/plan.md` (section 1) has four framings and
three sequences, and `instructor/run-sheet.md` has all three with clock times. Once Alp picks, trim the run sheet and
talking points to match.

## Commands

tools/quarto.sh preview site     # live preview at http://localhost:4848

## Keeping things consistent

- **A prompt appears on the page, in `instructor/prompts.txt`, and for the starter prompt, in the PARTS figure.** The
  page is the source; run `extract_prompts.py` after any change. The starter prompt is also in `instructor/chat.md`.
- **The prompts match the demo.** The project instructions file in section 5.2 is the demo's `CLAUDE.md` with the
  audience left as a blank. The upgrade prompt and the four next-change prompts are the ones the demo and its
  `live/*` branches were built from; the times in `_variables.yml` (`times`) come from `instructor/dry-run.md`.
- **A prompt goes on the page only after it has run,** and `instructor/dry-run.md` says what has. The Canvas prompts
  had not been run in NC State's Gemini on 2026-11-23.
- **Claims about NC State's rules carry a date** (`security.checked-date`) and link to the approved AI list. Recheck it
  the day before the session.

## Gotchas

- **Quarto isn't installed on this Mac;** `tools/quarto.sh` runs 1.10.18 from Docker. When Docker's amd64 emulation
  stops (`exec format error`, as on 2026-11-24), the macOS build from Quarto's v1.10.18 GitHub release runs natively
  from a scratch folder: `<folder>/bin/quarto render site`.
- **In this Quarto version the title slide is `section.quarto-title-block`,** not `#title-slide`.
- **In the deck, an HTML comment above the first heading becomes an empty slide.** Put notes in the YAML header.
- **The activity in the screenshots shuffles,** so a new capture shows different objectives. `shoot.mjs` evals need
  `window.scrollTo({top, behavior: 'instant'})` because of smooth scrolling.
- **The GitHub repo and the go link don't exist until Alp creates them,** so `check_links.py --web` reports both as
  404 until then.
